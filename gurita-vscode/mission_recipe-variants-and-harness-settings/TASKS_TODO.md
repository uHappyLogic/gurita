## Harness Dropdown on Settings View Line Rows

In the settings view of Gurita for VS Code (`gurita-vscode/src/lineValues.ts` rewriting, `gurita-vscode/src/variantEdits.ts` storing, `gurita-vscode/src/pane.ts` and `gurita-vscode/src/webview/page.ts`), the harness shown beside each row that carries model and effort dropdowns becomes a dropdown offering Claude Code and Antigravity, and a pick rewrites the line onto the picked harness and writes it to the per-user store exactly as a model or effort pick is written: the rewrite keeps the line's prompt and its headless or interactive form (`claude -p "…"` to `agy -p "…"`, `claude "…"` to `agy -i "…"`, and back), takes the picked harness's first listed model, and keeps the line's effort when that harness's effort list offers it, taking its first listed effort otherwise. It is needed so that the harness is one more control per row beside model and effort, and it replaces the recorded decision that the extension only replaces a value a line already carries and never inserts text into a line; a Codex line keeps its harness as text beside its model dropdown, and Codex is not offered in the dropdown. It is verified by unit tests of the rewrite over shipped lines in both directions and both forms, by page and pane tests of a pick reaching the store and the redrawn row, by `npm test` passing, and by `gurita-vscode/README.md` describing the control.
