## Seven-Step Workflow Diagram on Mission Pages

Each mission page's workflow diagram, drawn by `gurita-vscode/src/webview/page.ts` with its filled block chosen in `src/workflow.ts` and its rules in the stylesheet of `src/pane.ts`, becomes one line of seven blocks joined by arrows (define, first review round, additional review round, derive tasks, execute tasks, follow up tasks, finish) with no frames, loop arrow, or handoff label, the two optional blocks (additional review round, follow up tasks) drawn with a dashed border and the five required ones solid, so the page shows the choices a person makes rather than the framework's inner steps; the additional-round block reads plain "additional review round" while git holds at most one `Requirements-review:` commit for the mission and then carries the live count of those beyond the first ("additional review round 1", "2", and so on). The filled block, which keeps its pulse while a run is held, is first review round for a defined mission with no open question, no task, and no review commit and while a question lacks alternatives or a pick and at most one review commit stands, additional review round while a question lacks alternatives or a pick and two or more stand, derive tasks when every open question has a pick or when none is open and no task exists on a defined mission whose review commit stands, execute tasks while tasks remain and no question is open, and finish for a started mission with no open question and no task; define and follow up tasks are never filled, an open question still outranks a remaining task, and no block is filled when a document or git read the choice needs failed. Verified by unit tests over every state and count, `gurita-vscode/README.md` and the source comments describing the seven steps in place of the eight blocks, and `npm test` and `npm run package` passing under Node 22 through nvm.
