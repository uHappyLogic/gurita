## Purpose

This node is for maintainers of `tests/`, the pytest suite of the six tools under `core/tools/` and of the plugin's fixed shell calls, beside the build's in-process rendering test, the banner and icon checks, the fixed console lines check, and the knowledge tree check. `uv run pytest` collects it together with `gurita-vscode/runner_tests/` (the `testpaths` of `pyproject.toml`), and `pythonpath = ["core/tools"]` makes each tool importable by its module name, while the tool tests drive each tool end to end as a subprocess under the running interpreter, so every exit status, stdout, and stderr they see is exactly a caller's. Each test module's docstring says what it covers and each fixture in `conftest.py` is documented where it is defined, so this node holds only how the suite is organised and run and the rules an edit here keeps; a rule a test pins is stated in the node of what it tests, which the pointers beneath the rules name. `fixed_console_lines.tsv`, the one data file standing here, lists every fixed console line, its format stated by the docstring of `test_fixed_console_lines.py`, which reads it. The on-demand host suite is `host_tests/`, not this folder, although its fixture project stands under `tests/fixtures/host_project/`.

## Rules

- **One flat `test_<name>.py` per subcommand or concern, golden fixtures under `tests/fixtures/`.** A module is named for its subject (`test_task_list_remove.py`, `test_missions_since.py`, `test_commit_retry.py`, `test_banner.py`), no subdirectory holds a test module, and the golden inputs (question documents, task lists, `requirements.md` files, the host suite's fixture project) stand under `tests/fixtures/`, read in place. Reason: a change to one subcommand or concern finds its tests by name, and one directory keeps one `conftest.py`. Retired forms: none recorded.
- **Every git repository a test builds runs on the shared fixtures in `conftest.py`.** `environment`, `git`, `run_call`, the `repo` factory seeding the named fixture missions, the commit tool's `run_commit`, and the missions tool's `run_missions` and `make_commit` stand there, moved out of `test_sweep_batched_call.py`; `test_sweep_compact_view.py`, which builds no repository, keeps its own `environment` and `run_call`. `conftest.py` sets `sys.dont_write_bytecode`, so importing a tool leaves no `__pycache__` under `core/tools/`. Reason: one fixed environment and git identity for every repository, and the build renders every file under `core/` into every host tree, so bytecode left there would ship. Retired forms: per-module copies of the git fixtures.
- **Both runs pass before a tool change is committed, and the build's rendering test is the one pinned-only module.** The pinned run uses the `.python-version` interpreter and the locked `dev`-group pytest; the floor run bypasses the build tooling's `requires-python = ">=3.11"` on purpose, since the tools need nothing from that project, and the suite stays on the pytest API both runs share. `test_build_rendering.py` imports the build, which needs `tomllib` and PyYAML, so it skips itself at module level below Python 3.11, keyed on the interpreter version and before any import of the build: the floor run reports it skipped and the pinned run never does, and no pytest command, `conftest.py`, or `pyproject.toml` setting excludes it. Every other module runs under both, a test that only reads tracked files (the console-lines, banner, icon, and knowledge-tree tests) included. Reason: two bracketing runs replace a version matrix because stdlib availability is monotone across minors. The literal `3.9` has three homes, changed together: the root README's prerequisite, the `define-mission-goal` check, and CI's floor run. Retired forms: a version matrix, an exclusion of the rendering test by command or configuration.
- **A fixed-call test extracts its call from the rendered Claude Code tree, never from a copy.** Each of the six takes the one fence under `hosts/claude/` holding a command only that call carries, with nothing added to the runtime file to mark it, replaces the placeholders, and runs the call under bash in a temporary repository, under both interpreters: `test_alternatives_agent_read_call.py` the alternatives agent's read call, also under zsh where installed, beside a bare `echo =====` variant asserted to lose the second read there; `test_commit_procedure_call.py` the commit procedure's call, also under zsh, a body holding a backtick, `$`, `"`, an apostrophe, and a backslash landing exactly with nothing run, beside a removal and the subject-only form; `test_sweep_compact_view.py` and `test_sweep_batched_call.py` the answer sweep's two calls, the conflict section taken from the one fence holding `replace` and a raw heading holding a backticked command landing byte for byte; `test_completion_call_lock_retry.py` the inline completion call against a `.git/index.lock` released within the commit tool's retry window and one never released; and `test_parallel_completion.py` the completion agent's step-5 call and the orchestrator's commit-from-file call for two fixture missions at once, each commit carrying only its own paths and exactly its own bar, an empty bar and an absent or empty body file each committing nothing. Rebuild `hosts/` before running them on a `core/` change, since they read the committed tree. Reason: a copied call keeps passing while the shipped one breaks, and the shipped text is what a runner is told to run exactly as shown. Retired forms: a call copied into a test, a marker added to a runtime file to locate a fence.
- **A test pins a rule stated in another node and never restates it.** A test's assertions follow the rule as the node of what it tests states it, so a rule, its tests, and the rendered trees change together. A message a fixed call prints mid-run to its own runner (`acceptance bar empty`, `dirty before start`, the orchestrator's `path file empty`) is pinned by behaviour in the fixed-call tests and is not a row of `fixed_console_lines.tsv`. Reason: a rule's one statement is where an edit to what it governs finds it, and a second one would drift with no check failing. Retired forms: the Markdown table of fixed console lines in `docs/skill-reference.md`, which the console-lines test once parsed.
- → `core/tools/README.md#rules` — Each tool's contract and refusals, its self-containment the parity tests assert, and the commit tool's retry schedule the lock-retry test holds a lock against. Read it before changing a tool test's expectation.
- → `core/skills/README.md#rules` — Literal shell commands, the skill layer's committing, the answer sweep's batched call, and the fixed first lines the console-lines test checks. Read it before changing a fixed-call test or a row of the lines file.
- → `core/agents/README.md#rules` — The completion agent's body and path files, its empty-bar test, and the orchestrator's file tests, which `test_parallel_completion.py` pins. Read it before changing that test.
- → `CLAUDE.md#rules` — The knowledge tree's pointer form, part sets, folder coverage, and budgets, which `test_knowledge_tree.py` checks over the tracked files. Read it before changing that test or what it counts as a node.
- → `core/shared/README.md#rules` — The bar's record form, one `- ` bullet per criterion and nothing else, which the completion-call tests assert as each commit's whole body.
- → `scripts/README.md#rules` — Slot rendering, which `test_build_rendering.py` pins, and the banner and icons as derived output, which the banner and icon tests compare with their generators' output (the listing PNG by decoded image).
- → `host_tests/README.md#rules` — Why the fixture project's mission under `tests/fixtures/host_project/` is tracked under a name the discovery pattern does not match. Read it before renaming anything there.

## Commands

- `uv run pytest` — the pinned run, collecting `tests/` and `gurita-vscode/runner_tests/`.
- `uv run --no-project --python 3.9 --with pytest pytest` — the floor run; run both before committing a tool change.
- `uv run pytest tests/test_<name>.py` — one module, under the pinned interpreter.
- `uv run scripts/build_hosts.py` — rebuild the host trees the fixed-call and console-lines tests read.

## Pointers

- → `tests/conftest.py` — The shared tool runners and git-repository fixtures, each documented where it is defined. Read it before building a repository in a new test.
- → `tests/fixtures/` — The golden fixtures and the host suite's fixture project. Change one only together with every test that reads it.
- → `.github/workflows/drift-gate.yml` — CI's one job, which runs `--check` and then both pytest runs. Follow it to see what a pull request must pass.
- → `gurita-vscode/BUILDING.md#building-and-packaging` — The extension runner's own tests under `gurita-vscode/runner_tests/`, which both runs here collect. Read it before changing a runner test.
- → `CONTRIBUTING.md#development` — The build loop and both test runs, for a contributor.
