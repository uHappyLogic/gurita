## Purpose

For maintainers of `core/skills/`, each `SKILL.md` its skill's exact behaviour: the rules a skill edit keeps. Every `scripts/hosts/<host>/settings.toml` excludes this file.

## Rules

- **Frontmatter is a routing label.** Each `SKILL.md` and agent file has `name` and an unquoted one-clause `description`, at most 25 words, no colon or semicolon, `yaml.safe_load`-able, no exception; an agent's keeps its invocation clause. Reason: it routes, never records. Retired forms: provenance, mechanics, cross-references, trigger lists (homed in `docs/skill-reference.md`).
- **Tidy vs. record.** `review-mission-requirements` alone authors blocks, removing one only as cleanup (a covering decision, an exact duplicate), flagging in doubt. Its `## Decisions` consistency step adds per conflicting pair one block naming both `###` headings, asking which stands, editing neither, in its `Requirements-review:` commit, so it holds convergence; each opens with one fixed phrase. Each `## Noted contradictions` note becomes such a block and is deleted, or is dropped when a block flags the pair or an entry is gone or reconciled, never re-judged. A conflict answer's whole record, in every runner, is the losing entry's rewrite; the sweep tells one by the phrase as exact prefix (older blocks get the append), noting nothing. Reason: a block has no kind marker; re-weighing a note is not tidying; an appended correction leaves both texts standing. Retired forms: a sweep contradiction advisory, an appended correction.
- **Two annotating passes, split at enumerate vs. pick.** `provide-alternatives-to-all-open-questions` dispatches one read-only agent per bare block as `ALTERNATIVES_PARALLELISM` states, no order or cap, siblings scope only, and embeds and commits landed files in batch calls, one subject-only `Alternatives-annotation: <Short Title>` commit per question. `recommend-all-open-questions` picks inline in any order, leaves standing picks (idempotent by the `--without-*` filter and the tool's refusal), takes the best surviving option, skips a block none survives, and writes, commits, and sorts in one uncapped fixed call: per block `embed --recommendation` then, on exit 0, `lift` for the body; one `Recommendation-annotation: <MISSION_DIR>` commit if the body is non-empty; the sort under `Question-ordering: <MISSION_DIR>`. Refusals get one joint re-send, then the advisory. Both gather once, need no clean tree, and keep stale tags. Reason: scope-only siblings make parallelism safe; one `embed` per block keeps per-block refusal; separate steps cost a median 6 turns against two. Retired forms: a per-question recommendation commit, a sequential recommend-agent sweep, most-significant-first ranking, separate embed, lift, commit, and sort steps.
- **Element rendering.** The alternatives agent writes only `<alternative>`; the recommendation pass renders `<applied-principle>` per bearing principle, `<depends-on question option/>` per assumed sibling (no option-less form), and one `<recommendation option>`, as siblings; indentation, escaping, and order are the tool's. Attributes stay hand-rendered for good, a `"` refused by the tool and corrected once. Reason: citations outside the text keep `## Decisions` provenance-free; the refusal is never silent. Retired forms: nested elements, escaping added anywhere.
- **The answer sweep is an inline single writer ordered by `walk`, recording in one batched call.** One fixed call gathers and views (`list --with-question`, a `walk`-fed `lift` loop), the question file never read whole, `requirements.md` read whole in that turn. One fixed call carries a section per walked question in walk order, uncapped: a guard printing `dirty before start` if either mission file changed; per section a lift, stderr silenced, a failure the silent skip, a fold (a conflict section's `replace`), `remove` with `--option` copied from the view, a `Recommendation-answer: <Short Title>` commit with the lifted line as body printing `answer commit landed`; a failure prints `stopped at` and the title, the tree resumable; a closing `walk` id is an anomaly. Picks are recorded as given: no mooting cascade, advisory, or note. It follows no procedure, using only the answer core's fold rules and first two analyse questions. Reason: each commit's assumed siblings are recorded; revert needs one commit per answer; the old loop cost 2.22 turns per answer. Retired forms: a whole question-file read, per-answer `locate`, the `=====` separator, commits outside one call.
- **Hand answers.** `answer-open-question` records a literal only, the retired sentinel `record the recommendation` (exact whole match) stopping with a redirect. It and `answer-open-question-with-alternative` split on the first `.` followed by whitespace, stopping without one; `discuss-open-question` splits alike, the rest an optional note, none a title alone. The alternative answer is skill-only, lift-then-delegate inlined, its guards the `lift` `Error:` line. Reason: choosing an alternative is human judgment; shared means two runners; a bare-`.` split cut dotted file names, while recipe lines already write `<Short Title>. <…>`. Retired forms: a sentinel mode, a bare-`.` split, a longest-title match.
- **Answer subjects are provenance discriminators, not a harvest filter.** Capture walks `Manual-answer:`, `Alternative-answer:`, `Recommendation-answer:` on `open_questions.xml`; overrides signal principles, accepted recommendations are evidence, agreements unprompted. It rebuilds from removed diff lines keyed on the tag, un-escapes entities itself, writes the store whole, commits on one confirmation or restores its own snapshot, and commits nothing on no capture; finish never invokes it. Reason: a recommender cannot supply the guideline it lacked. Retired forms: a per-element ignore list, restoring `HEAD`.
- **A bad answer is corrected by revert-then-re-answer.** One commit per answer makes the revert reopen it; a principle that steered wrong is reconciled by the next capture. Reason: nothing more is needed. Retired forms: a correction skill.
- **`modify-mission-goal` edits only `## Goal` and clears only the picks it undermines.** It names them by the hand-answer tests, doubt stripping, clears them with one non-transitive `strip --recommendation` keeping alternatives, and commits both files under `Goal-revision:`, changing nothing else; `discuss-open-question` offers it, `answer-open-question` never. Reason: an old-goal pick would reach the sweep; a goal settles no tagged sibling outcome; answering and reshaping differ. Retired forms: a transitive clear, a cascade.
- **`define-mission-goal` places a mission by a required `--at <scope>`.** The scope holds the work's core, never its footprint, recorded nowhere; `discuss-mission-goal` proposes it as deep as the core allows, the root only for the project itself, never widened. The skill probes git, then `python3` 3.9, each with its own stop, passes the scope verbatim, and commits the printed subject and path. No skill picks the next mission. Reason: a recorded footprint makes the gate cautious; a high mission overlaps all below; the definition is the first write. Retired forms: a default scope, a recorded footprint.
- **`finish-mission` removes the mission's directory, and that commit is its record.** After its checks it makes one `Mission-finish: <MISSION_DIR>` commit through the commit procedure, the directory its removal, the context file a path only when edited for lasting changes. Its body, read back by the missions tool, is the `# ` title as it stands, a blank line, `- ` bullets, a trailer allowed. A standing note stays at the parent. Reason: finished means gone, a revert revives it, no shared file conflicts. Retired forms: an `## Outcome` section, a tree growing forever.
- **`derive-tasks` resolves a conflicting pair by recording order, never blocked.** Its precondition stays the empty `list`; the later-recorded entry, read from the commit adding it (blame or pickaxe), governs, noted pairs taken as noted, nothing flagged. Reason: of 20 runs with the old advisory, 12 derived at once, one entry winning silently. Retired forms: a flag or stop, file-position order.
- **Environment context comes from the context file** the `CONTEXT_FILE` slot names (`/init` once), read by the starting-state procedure, `derive-tasks`, and the completion procedure. The bootstrap writes only `## Mission Workflow`, from `core/shared/workflow-guidance.md`. Reason: that is the section's one home. Retired forms: a bootstrap writing environment context.
- **Committing is a property of the skill layer.** Every file-changing skill commits exactly its own paths under a function-derived `<Marker>: <descriptor>` subject, a mission named by its resolved path. `commit-procedure.md` is one commit-tool call, BODY captured by `{ body="$(cat)"; } <<'EOF'`; procedures stay commit-free. A marker echoes only on empty `out`. `complete-all-tasks` commits each `DONE` under `Task-completion: <TASK_NAME>` from the body and path files, typing no path or bar, a missing one stopping the run; inline `complete-task` feeds `--path-file -` from a heredoc. Task-file writers chain write and commit behind `&&`; `init-mission-base-workflow` commits under `Workflow-bootstrap: missions`. Reason: a quoted body expanded `$`; without a pathspec another run's staged files rode in. Retired forms: `git add -A`, `Tasklist-completion:`, a non-committing exemption, the role-based split, `Task run committed nothing — no task staged a change.`, agent staging, a whole-index commit.
- **Shell commands are written literally.** A fixed call is run as shown, only placeholders replaced. A multi-call runner writes the full tool command each time, never via a variable, alias, or function of its own, and never holds a path in a variable; a value set and used in one call (`out`, `bar`, `heading`, a loop value) is exempt. Free text enters by a quoted group-fed heredoc (the sweep's heading as `--section "$heading"`), each with the delimiter clause; the alternatives agent's reads join on a quoted `printf` line. Reason: zsh splits no unquoted variable and reads a bare `=` word as `=cmd`; the nested capture fails on bash 3.2; a quoted heading ran a backticked command. Retired forms: a held command or path list, a bare `=` separator, the nested capture, a literal `--section "<Heading>"`, `$'\n'`, `echo -e`.
- **Reports are terse and open on a fixed line.** One fixed identifier-free status line per run, none per item, the recommendation pass's two read from its markers; beside it only git-absent decision-critical advisories (convergence, untraceable requirement, skipped questions, the sweep's anomaly, each id the alternatives pass's closing `list --without-alternatives` prints). Every no-op and stop opens with one fixed unique whole first line, detail below; a refusal is one condition; a shared procedure owns its stop's line. Review prints its convergence line exactly when its closing `list` prints nothing. Reason: no skill sets an exit code; a chain reads only the final message. Retired forms: a free-worded verdict, a `report-procedure.md`.
- → `tests/fixed_console_lines.tsv` — Every fixed line, its source and kind. Change a row with its line.
- **Pre-split missions get no compatibility.** The first 27, older than `open_questions.xml`, stand only in history; a question skill pointed at one stops on the tool's `Error:` line. Reason: history reaches them. Retired forms: a conversion.
