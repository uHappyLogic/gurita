## Purpose

This node is for maintainers of `core/tools/`, the six stdlib-only Python 3.9+ tools every host tree carries byte-identical: the open-question tool, the task-list tool, the fold tool (`requirements.py`), the mission-definition tool, the commit tool, and the read-only missions tool. Each tool's `--help` and module docstring state its subcommands, output, and refusals, and its tests under `tests/` pin them, so this node holds only each tool's rule, its reason, and the forms that must not return. No host renders this file: every `scripts/hosts/<host>/settings.toml` excludes it.

## Rules

- **Every tool is one self-contained file.** It carries its own stdin reader, error type, main, and atomic writer and imports no sibling (a parity test asserts it); its source holds no host name, no placeholder of its own, and no bare placeholder opener. A document writer (open-question, task-list, fold, definition tool) touches no git; the commit tool is the one tool that writes through git, the missions tool the one that reads it. Every call site runs a tool as one fixed command, a document writer as `python3 <plugin root>/tools/<tool>.py <subcommand> <MISSION_DIR> …`, the directory never the file path, free text on stdin as a quoted heredoc, never `python`; runtime prose states a tool's contract in at most one sentence per site. Reason: each tool renders as one runnable file into every host, and a git step differs per runner, so it rides beside the call. Retired forms: a shared module, a git step inside a document writer.
- **The open-question tool is the only writer of `open_questions.xml` once the definition tool has created it, not its sole reader.** An inline skill or a procedure it follows may read the file whole for reasoning; a dispatched agent reaches it only through the tool, a ban scoped to this one document. There is no hand-edit exception: a stale set or pick is cleared with `strip` or `strip --recommendation` and a re-run. `add` alone refuses a new Short Title whose folded form holds `/`, `"`, `$`, backtick, `\`, control character, or `.` before whitespace, or opening with `-` or ending in `.`; `embed --alternatives` alone refuses an id holding `"`, `$`, backtick, or `\`, or a spaced em dash; `embed --recommendation` needs no check of its own. The review pass's Short Title bullet lists the refused set so a title is right the first time. Reason: a title is copied into the alternatives agent's return file name, double-quoted shell arguments, a positional argument with no `--`, the hand-answer `. ` separator, and the document; an id into the same quoted arguments, and `lift` joins option and rationale with the spaced dash every reader splits on, so `Wait — then decide` read back as `Wait`. One check where a name is created closes every position, refuses no title a person writes (dotted file names, inner hyphens, entities stay legal), and leaves standing blocks loadable, `load_document` checking duplicates only. Missions older than the document get no compatibility: their files are never converted and a question skill stops on the tool's `Error:` line. Retired forms: the `awk`/`sed`/`grep` boundary-line idiom, any hand edit, prose restating escaping, indentation, boundary tokens, or reconciliation.
- **The task-list tool is the only writer of `TASKS_TODO.md` once created, and changes no read of it.** `initialize` (derive-tasks), `insert` (submit-task), `remove` and `replace` (the completion procedure) parse the whole file and render one canonical layout, discarding the preamble for the fixed heading and normalizing drift silently. A `---` is a separator only before a column-0 `## ` heading or the end of the file, every such line is a heading with no fence exemption, and every section written carries its `---`. Titles match by exact folded equality, refusing partial or shared ones, and uniqueness is checked in `TASKS_TODO.md` only. `insert` takes the title as an argument and requires one of `--end`, `--before`, `--after`; an unknown anchor is refused. `initialize` replaces the file whole with no refusal. `remove` takes out one section and renders it nowhere; `replace` rewrites one queued body, keeping heading, position, and `---`, refusing an empty body. A new title (`insert`, each `initialize` heading) holding `"`, `$`, backtick, or `\`, or opening with `-`, is refused. The format of `core/shared/task-format.md` is never validated, the empty-bar test lives in the completion calls rather than the tool, and any failure leaves the file byte-for-byte unchanged. Reason: the section move was the step runners hand-coded (about three in four of 202 measured agents), position encodes dependency order, a guessed match removes the wrong task, a completed task's record is its `Task-completion:` commit, and a title rides in quoted and positional arguments. The `TASKS_DONE.md` held by missions defined before completed tasks moved into commits stands only in history, read by no runner and recreated by no tool; for those tasks it stays the one record of the bar, a partial compatibility accepted. Retired forms: the four-call `Read`/`Edit` move, ad-hoc slicing scripts, `move` with its `**Verified:**` rendering and two-file rollback, a per-brief append, an append fallback on an unknown anchor.
- **The fold tool is the answer sweep's writer of `## Decisions`, not the section's sole writer.** Only the sweep calls `fold` and its conflict section `replace`, each with a required `--section`; the single-question skills edit by hand. Both are byte-preserving splices writing the body verbatim with outer blank lines trimmed; `fold` creates an unmatched subsection at the end of `## Decisions`, `replace` rewrites an existing body and creates nothing. Either refuses a body line opening at column 0 with `## ` or `### `, and a file holding no or several `## Decisions` headings; every format rule stays in the answer core's fold step. Reason: a file edit cannot be chained with `remove` (42% of 814 sweep folds were ad-hoc scripts), the file is still hand-written so nothing may be normalized, and a heading line in a body once duplicated `## Out of Scope`. Retired forms: a whole-file render, an optional `--section`, a `--replace` flag on `fold`, an entry-level target, a `remove --decision` in the open-question tool.
- **The definition tool requires `--at <scope>` and names the mission by its path.** It normalizes the scope lexically, refuses an empty, absolute, `..`-climbing, or non-existent one, and refuses whitespace or a shell-syntax character as its `--help` lists, then creates only `<scope>/mission_<slug>/` exclusively, with no number, and prints the subject and the path. Reason: a definition that forgot its placement must fail rather than land at the root, every later call writes the path unquoted, and the `mission_` prefix gives one discovery pattern. Already-defined missions are not checked. Retired forms: a default scope, a numbered directory, quoting rules downstream.
- **The missions tool reads live missions from the tree and finished work from commits, writing nothing.** Its eight queries share one parser, one `Error:` contract, one discovery pattern `**/mission_*/requirements.md` with no exclusion (so the host suite's fixture mission stays unmatched until seeded), and one scope rule by whole path components. Started is read from the log (`--diff-filter=M` on the task list), never from the list, so a mission whose tasks all completed still holds its scope. `live` keeps its listing print; with a mission path it lists the other live missions, defined ones included, whose scope overlaps. `gate` prints overlapping started missions and exits 0 either way, and refuses a path naming no `mission_` directory. `tasks` reads `Task-completion:` subjects only, sorts newest first by author date, joins the mission by its task list (none or several matched print under a placeholder, kept for `2202e59`), indents bars under `--with-body`, and `--bodies N` bounds bars, never titles. A finish is read only from a path-form `Mission-finish:` subject and presence wins over the log. `missions --mission` prints the named mission's scope overview and `--last N` bounds its finished lines in the tool; `record` takes no bound; `since` finds its anchor by subject and path, its broad form skipping commits inside a defined sibling and counting its own `Goal-revision:` commits, its `--missions` form other missions' task and finish commits only. `gate` and `since` alone refuse a shallow clone; every other read takes what the log yields. A trailing all-`Token: value` paragraph is dropped from every body. `show`'s and unbounded `tasks`' whole prints are accepted as they stand. Each caller's use and failure handling is stated with that caller. Reason: the record of finished work moved into commits, a `git log` typed at each site is the hand-rolled code tools replace, and a silent gate or staleness read would let runs collide. Retired forms: a done file, reading `Tasklist-completion:` commits, a stored anchor, a second discovery pattern, a split into two tools before a reason appears.
- **The commit tool holds every git write's mechanics.** It runs the dirty-own-path guard, stages with a path-scoped `git add` only the named paths `git ls-files` still finds (so a path removed by `git rm`, `git mv`, `rm`, or `mv` commits as a removal and a mistyped one is still refused by git), removes each `--remove` path with `git rm -r` inside the same retry, and commits with every named path as pathspec. It reads paths from arguments or line-exact from `--path-file` (`-` for stdin), with no word splitting. It repeats a git write only on exit 128, on one fixed schedule (16 attempts 0.25 seconds apart, accepted though a non-lock failure also waits it out), reading no message text; it prints nothing on a commit and exits 0 on its one fixed no-op line, every failure one `Error:` line. Reason: a commit without a pathspec takes the whole index, so another run's staged files rode into a `Task-completion:` commit; a held lock must be absorbed while a crashed one surfaces; a retry each caller retyped would be hand-rolled code. The rules on who commits what, under which subject, are stated with the commit procedure, skills, and agents. Retired forms: `git add -A`, a whole-index commit, a shell retry loop, a marker argument, a lock of the plugin's own, a private index, `--pathspec-from-file`.

## Commands

- `python3 core/tools/<tool>.py --help` — the tool's contract.
- `uv run pytest` and `uv run --no-project --python 3.9 --with pytest pytest` — run both before committing a tool change.
- `uv run scripts/build_hosts.py` — copy a changed tool into every host tree.

## Pointers

- → `tests/` — One test file per subcommand or concern pins each tool's contract. Change a tool's behaviour together with its tests.
