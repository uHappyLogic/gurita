## Purpose

For maintainers of `scripts/`: the one generic host build (`build_hosts.py`), the host definitions under `scripts/hosts/<host>/` it renders `core/` through, the version script (`set_version.py`), and the two render scripts (`render_banner.py`, `render_icon.py`). Each script's module docstring is its reference (inputs, outputs, check set, exit codes) and each definition's `settings.toml` comments its own keys, so this node holds only the rules an edit here keeps, with reasons and retired forms. The `README.md`, `CONTRIBUTING.md`, manifest, and workflow files inside a definition are templates the build renders into `hosts/<host>/`, not nodes. No script touches git.

## Rules

- **`hosts/<host>/` is pure build output.** Rebuild after any change under `core/` or `scripts/hosts/` and commit the rebuilt trees with that change, so `main` always passes `--check`; the trees are never hand-edited and are published verbatim into `uHappyLogic/gurita-<host>` at release. `--check` is run by a maintainer or CI, never a git hook; the CI workflow has no path filter and is one job, never a matrix. Reason: a `paths` list would be a hand-maintained copy of the build's input set, and the drift gate must see every change. Retired forms: a hand edit under `hosts/`, a git hook, a path filter, a matrix.
- **One generic build, hosts declared as data.** Adding a host means adding a definition directory under `scripts/hosts/`; no host-specific Python exists. A definition's `[layout]` maps all four `core/` directories, every one inside its `plugin_dir` (the path from the tree root to the runtime plugin root: empty for Claude Code and Antigravity, `plugins/gurita` for Codex), and it declares every wording slot the other definitions declare. Every definition lists each `README.md` node under `core/` in its `exclude` key, so no node reaches a host tree and the build's Python stays unchanged. Reason: one validated path for every host, and a definition is checked before any build runs. Retired forms: host-specific code in the build.
- **Host wording differences are named slots, never markers, duplicated files, or capability-conditional prose.** A sentence or phrase that differs between hosts is a `{{SLOT_NAME}}` placeholder in `core/`, filled from every definition's `[slots]` table; `slot-declaration` keeps the declared name sets identical and each name used in `core/`, and `unfilled-placeholder` catches one a host leaves undeclared. Reason: `core/` never names a capability for the runner to branch on at run time, because a branch the host lacks is dead text in its tree that a runner can still follow, so each tree describes only its own mechanism. Each value is written from that host's own hands-on check, never copied from another's, and host trees are not expected to agree: no byte-identity between them is kept or tested, rendering being tested by `tests/test_build_rendering.py` instead. By convention each value, one-word and empty ones included, is one file under the definition's `slots/`, bound as `NAME = { file = "slots/NAME.md" }` with its comment above the entry; the inline string form is still accepted and nothing refuses it, so the convention is not a check. A value carries no placeholder but `{{PLUGIN_ROOT}}`. Retired forms: markers, duplicated per-host files, capability-conditional prose, the `AGENT_TOOL` and `ALTERNATIVES_AGENT` slots (their wording now written literally inside each `ALTERNATIVES_REPAIR` value).
- **The alternatives pass's host-dependent passages are three slots, each value describing only its host's one dispatch and wait mechanism.** `ALTERNATIVES_PARALLELISM` is the opening paragraph's phrase saying whether the per-question dispatches run together; `ALTERNATIVES_REPAIR` opens the repair sub-step ahead of its fixed corrective message, fill rule, and one-repair cap (which stay in `core/`), holding this host's repair branches and how the run waits on repairs; `ALTERNATIVES_CONCURRENCY` opens step 3 and governs how returns are collected. The Claude Code and Antigravity values send every dispatch at once, none blocking, and batch on each wake-up with landed returns, no shell loop or event monitor serving as the wait. The Claude Code value also holds a dispatch the host refuses for its concurrent-subagent limit as pending, despite the refusal's "Do not retry", resending one held question per ended agent on each wake-up, the wait and the closing check not ending while one is held, naming no number so it survives a changed limit. Reason: 360 dispatches past the limit were refused in 41 field sessions, and in 3 of them 12 questions were never resent and stayed bare. The Codex value dispatches rounds of at most the session's `agents.max_threads`, calls `wait_agent` until the round's last final message arrives, then batches once, a refused round's repairs getting their own wait and batch before the next round, so repairs never share a wait or take a slot. These two slots hold the pass's only host-dependent waiting wording; the batch has no slot, and the scratch directory, dispatch prompt, and agent file are host-neutral. Retired forms: a value describing more than its host's mechanism, a count written into the refused-dispatch step.
- **Agents are dispatched through each host's dispatch slot values, phrased descriptively.** The Claude Code tree names an agent by its namespaced registry name (`gurita:<agent>`), the Antigravity tree by the bare name its own `agents/` directory carries, with no agent-loading file or build change, and the Codex tree runs its generic subagent told to read and follow the plugin's Markdown agent file. Reason: Codex documents no way for a plugin to ship a custom agent. Retired forms: a Codex TOML agent file, a registration step, a format conversion in the build.
- **Rendered files carry no editor-facing prose and name no host.** They hold only what the runner needs: no `## Rules` section (a rule lives in the step it constrains or the opening paragraph), and rationale lives in the excluded nodes, never in a rendered file. A slot value names no host, its own included, and reaches its host's mechanism through that host's own identifiers (tool names, config keys, file and command names), otherwise saying "this host"; the agents' Claude-only `color` frontmatter key, stripped by the Antigravity and Codex definitions' `strip_frontmatter_keys`, is the one structural exception. A rendered tree never names another host's mechanism in any file, files rendered from `core/` and the host's own templates (README, CONTRIBUTING pointer, manifest, marketplace file, traffic workflow) alike, a contrastive mention of what this host does not use included; a link to the source repository is not a mechanism naming. Reason: each tree is published alone and read by a runner who acts on what it says. This is a rule, not a check: `host-name-in-core` scans `core/` only, so a slot value or template that breaks it passes the build and is caught in review. Retired forms: rationale or `## Rules` sections in rendered files, a mention of another host's mechanism in a tree.
- **A host's hands-on check is recorded in one place: the dated block heading its `settings.toml`.** It names the installed version checked and the points and values the run covered, and a re-check updates it. The comment above each slot entry says only what the value stands for and why, in mechanism terms, with no version. Reason: one dated record per host, while a version or observed fact elsewhere goes stale unseen. Retired forms: tool versions or observed-behaviour facts in slot comments, nodes, or the root context file.
- **`VERSION` is the one source of the version, written only by `set_version.py`.** The script writes `VERSION` and its three mirrors (`.claude-plugin/marketplace.json`, `pyproject.toml`, `uv.lock`) in lockstep, rendered in memory first so a failure leaves every file untouched, and writes nothing under `hosts/`, whose manifests the build renders from `VERSION`. Releases go through `/release-plugin`, never a bare bump: one `Release: <VERSION>` commit changing only version slots and the `CHANGELOG.md` entry, then each host tree published with `git commit-tree` into `uHappyLogic/gurita-<host>`; those repositories and every `traffic-data` branch are never hand-edited, and `TRAFFIC_TOKEN` is a fine-grained PAT on exactly the four repositories, kept in no local copy. Reason: one literal cannot drift from its mirrors. Retired forms: a version edited by hand in a mirror or a host manifest.
- **The banner and the extension icons are derived output, never hand-edited.** `render_banner.py` writes `assets/banner.svg` from `assets/banner.txt` (printable ASCII only) and `assets/banner-colors.txt`; rebuild `hosts/` after, since the build copies `banner.svg` byte for byte to every host tree's root beside its README, as it copies `LICENSE`. `render_icon.py` writes `gurita-vscode/media/activity-bar.svg` and `gurita-vscode/media/icon.png` from the banner's first and last arms and `assets/icon-centre-arm.txt`, the PNG through `zlib` and `struct`. Both are stdlib-only and run by hand after any change to a drawing. Reason: the tests compare each committed output with the generator's (the PNG by decoded image, since compressed bytes vary with the zlib build). Retired forms: a hand-edited SVG or PNG.
- **The traffic workflow's copies are kept in sync by hand.** Each definition's `.github/workflows/traffic-badges.yml` mirrors the root `.github/workflows/traffic-badges.yml`; find every copy with `grep -rn github-traffic-badge@ .github scripts/hosts` and bump the pinned SHA in all of them together. Reason: actions are pinned to SHAs bumped by hand, and the build renders but never compares the copies with the root file. Retired forms: none recorded.

## Commands

- `uv run scripts/build_hosts.py` — rebuild `hosts/` after any change under `core/` or `scripts/hosts/`.
- `uv run scripts/build_hosts.py --check` — the drift gate: fails if a committed host tree differs from a fresh build.
- `uv run scripts/set_version.py X.Y.Z` — bump `VERSION` and its three mirrors; releases go through `/release-plugin`.
- `uv run scripts/render_banner.py` — regenerate the banner SVG, then rebuild `hosts/`.
- `uv run scripts/render_icon.py` — regenerate the extension's activity-bar and listing icons.

## Pointers

- → `scripts/build_hosts.py` — Its docstring is the reference for definitions, slot forms, the check set, and exit codes. Read it before changing a definition key or a check.
- → `scripts/hosts/claude/settings.toml` — Claude Code's definition and dated hands-on block. Read it before changing a Claude Code slot value.
- → `scripts/hosts/antigravity/settings.toml` — Antigravity's definition and dated hands-on block. Read it before changing an Antigravity slot value.
- → `scripts/hosts/codex/settings.toml` — Codex's definition and dated hands-on block. Read it before changing a Codex slot value.
- → `tests/test_build_rendering.py` — The build's in-process rendering test, pinned-interpreter only. Extend it when rendering or a slot form changes.
- → `core/tools/README.md#rules` — The tool sources' own rendering rules (no host name, no placeholder of their own). Read it before editing a tool the build copies.
- → `CONTRIBUTING.md#development` — The build loop, both test runs, and the distribution repositories, for a contributor.
- → `.claude/skills/release-plugin/SKILL.md` — The release procedure that consumes `set_version.py` and `--check`. Follow it for any release.
