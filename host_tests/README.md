## Purpose

This node is for maintainers of `host_tests/`, the on-demand host suite. It drives the installed CLI of one host, chosen per run (`claude`, `agy`, or `codex`), with the real home directory, against the plugin copy that host has installed, and it stands outside the `testpaths` of `pyproject.toml`, so neither pytest run nor CI reaches it. The module docstring of `conftest.py` is its reference (the up-front prerequisite check, the run fixture, and each host's entry), each test module's docstring states what its run asserts, and `CONTRIBUTING.md` gives each host's install and refresh commands, so this node holds only how the suite is organised and run and the rules an edit here keeps. Three modules stand here: `test_plugin_root_resolution.py`, a dispatch-free `submit-task` run that reads a shared procedure and runs a `python3` tool at the installed copy's root; `test_subagent_write_tools.py`, each plugin agent dispatched directly with the real prompt its orchestrator would hand it; and `test_derive_tasks_refresh.py`, `derive-tasks` on a history that has moved since the starting state, committing a `Starting-state:` refresh before its `Task-derivation:` commit. `conftest.py` imports `tomllib`, so the suite runs under the pinned interpreter only.

## Rules

- **The suite runs only when named, against exactly one host.** The required `--host` option takes exactly one of `claude`, `antigravity`, or `codex` and has no default. Before any test the suite checks the named host alone, in order: its CLI on `PATH`, the installed copy that CLI reports (Antigravity's at its fixed global path), that copy present, and that copy equal, file for file and a missing or extra file included, to the host's plugin directory in the committed built tree. A run naming no host, an unknown one, or more than one, or missing one of these, stops before any test with one `host suite prerequisite missing:` line on stderr and a non-zero exit, never a skip, every stop on a host's own check naming that host's remedy. Reason: a run against an absent or stale copy says nothing about the committed tree, and a skip would read as a pass. Retired forms: none recorded.
- **The suite writes nothing to any installation.** Bringing a copy up to date is the maintainer's own act, by the host's documented install, which the stop line names. Every headless process starts with `PYTHONDONTWRITEBYTECODE` set, so no session writes bytecode into an installed copy, runs at the account's default model and effort, and is bounded by the suite's one wall-clock limit (`RUN_TIMEOUT`), the same on every host, no host's own time limit being passed; a run past it is killed with its whole process group and fails its test. Reason: the suite runs in the real home directory, and the equal-copy check means something only while the suite never changes the copy. Retired forms: none recorded.
- **The tests name no host.** A test reads a run's tool-call records only through the chosen host's entry in `conftest.py`, whose parser turns that host's record shape into the one shape every test reads (`ToolCall` and `Records`), and words a dispatching prompt through the same entry (`Dispatch`). A pass signal is a landed file, the host's own record of a tool call, or the seeded repository's git log, never the final message or a transcript. Reason: one test serves every host, and each host's record shape and dispatch mechanism stay in one place. Retired forms: none recorded.
- **Each host has one trigger set, and a change owes a passing run on each host whose set it touches.** A host's set is its definition directory (`scripts/hosts/claude/`, `scripts/hosts/antigravity/`, or `scripts/hosts/codex/`) plus the host-neutral paths `core/agents/*.md`, `scripts/build_hosts.py`, and `host_tests/` itself, so a change to a host-neutral path owes a run on all three hosts and a change to one definition a run on that host alone, made before committing. Reason: these are the paths that change what an installed copy does on that host, and the suite is outside CI, so the run is the maintainer's. Retired forms: none recorded.
- **Every test seeds its own repository from `tests/fixtures/host_project/`.** The fixture project's mission is tracked as `fixture.mission_pocket-ledger-foundations`, a name the missions tool's discovery pattern does not match, and `seeded_repo` renames it to `mission_pocket-ledger-foundations` in each repository it seeds, where the installed skills find an ordinary root-scoped mission; any further history a test needs is built through the plugin's own tools. Reason: the pattern has no exclusion rule, so a fixture mission tracked under a matching name would count among this repository's own live missions. Retired forms: none recorded.
- → `core/tools/README.md#rules` — The missions tool's one discovery pattern with no exclusion, and the fixed `python3` tool command `test_plugin_root_resolution.py` asserts the orchestrator ran at the installed root. Read it before renaming the fixture mission or changing that assertion.
- **A test pins a rule stated in another node and never restates it.** A test's pass signal follows the rule as the node of what it exercises states it, so a rule and its host test change together. Reason: a rule's one statement is where an edit to what it governs finds it. Retired forms: none recorded.
- → `core/agents/README.md#rules` — The two agents' returns `test_subagent_write_tools.py` passes on: the alternatives agent's one scratch file, and the completion agent's body and path files with nothing staged or committed. Read it before changing that test.
- → `core/shared/README.md#rules` — The starting state refreshed in place at task entry, which `test_derive_tasks_refresh.py` asserts from the log. Read it before changing that test's history.
- → `scripts/README.md#rules` — Each host's dispatch slot wording and the plugin-root rendering a host run exercises. Read it before changing a host entry's dispatch wording.

## Commands

- `uv run pytest host_tests --host claude` — run the suite against Claude Code's installed copy.
- `uv run pytest host_tests --host antigravity` — run it against Antigravity's installed copy.
- `uv run pytest host_tests --host codex` — run it against Codex's installed copy.

## Pointers

- → `host_tests/conftest.py` — The suite's reference: the prerequisite check, the run fixture and its bounds, and each host's entry. Read it before adding a test or a host entry.
- → `CONTRIBUTING.md#development` — Where each host's installed copy is found and how to refresh it, the remedies the stop lines name.
